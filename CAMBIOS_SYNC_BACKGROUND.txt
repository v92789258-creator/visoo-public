================================================================================
OPTIMIZACIÓN: CAMBIOS INSTANTÁNEOS EN UI + SYNC EN BACKGROUND
================================================================================

PROBLEMA:
━━━━━━━
Usuario eliminaba/agregaba producto pero tenía que ESPERAR a que se sincronizara
con la nube antes de ver los cambios. Esto podía tardar segundos o minutos.

SOLUCIÓN IMPLEMENTADA:
━━━━━━━━━━━━━━━━━━━━━
Cambio de flujo en guardar_productos() (utils/file_handler.py):

ANTES (BLOQUEANTE):
  1. Guardar JSON local
  2. Encolar cambio en sync_manager
  3. ESPERAR a sync_mgr.sync_now() ← ❌ BLOQUEA aquí
  4. Devolver al usuario
  5. UI se actualiza (después de esperar)

AHORA (ASÍNCRONO):
  1. Guardar JSON local ← ✅ INSTANTÁNEO
  2. UI se actualiza INMEDIATAMENTE ← ✅ USUARIO VE CAMBIOS
  3. En background (thread separado):
     - Encolar cambio en sync_manager
     - Iniciar sync hacia la nube (NO BLOQUEA)
  4. Devolver al usuario SIN ESPERAR ← ✅ RÁPIDO

VENTAJAS:
━━━━━━━━
✅ Usuario ve cambios INSTANTÁNEAMENTE (millisegundos)
✅ Sync a la nube corre en background (no bloquea la UI)
✅ Si no hay internet, usuario sigue viendo cambios locales
✅ Cuando hay internet, se sincroniza automáticamente
✅ NO hay delays perceptibles para el usuario

FLUJO TÉCNICO:
━━━━━━━━━━━━
def guardar_productos(username, productos):
    # 1. Limpiar caché
    limpiar_cache_usuario(f"productos:{username}")
    
    # 2. GUARDAR LOCALMENTE (SIN ESPERAR)
    with open(productos_file, 'w') as f:
        json.dump(productos, f)
    ← ✅ Aquí termina el guardado LOCAL
    
    # 3. SYNC EN BACKGROUND (threading)
    def _sync_in_background():
        sync_mgr.queue_change(...)
        sync_mgr.sync_now(...)  ← Esto corre en otro thread
    
    thread = threading.Thread(target=_sync_in_background, daemon=True)
    thread.start()
    
    # 4. FUNCIÓN DEVUELVE INMEDIATAMENTE
    ← ✅ Usuario no espera sync
